# Cadenza Tableau Version — Design

**Status:** Draft (design phase). Awaiting user review.
**Date:** 2026-05-17
**Owner:** Jesse Kartes
**Purpose:** Simplified Tableau Public companion to the live Streamlit dashboard, demonstrating tooling versatility for RevOps / Sales Operations roles where Tableau, Looker, or Power BI is the house BI tool.

---

## 1. Project pitch

A three-dashboard Tableau Public workbook that mirrors Cadenza's analytical story — Retention, Sales Performance, and Pipeline — using the same generated dataset and brand identity as the Streamlit version. Each dashboard surfaces the headline KPIs plus the engineered insight for its motion. The workbook ships to `public.tableau.com` and is linkable from resume / LinkedIn / Streamlit About page.

**One-sentence resume framing:**
> Built a three-dashboard Tableau Public companion to the Cadenza Streamlit app — retention cohort analysis, rep attainment & ramp, and pipeline coverage — using a Python pre-aggregation step to keep metric definitions identical across both products.

## 2. Hiring narrative — why a Tableau version exists

Most RevOps and Sales Ops job postings list **Tableau, Looker, or Power BI** as required tools — not Streamlit. The Streamlit dashboard proves the analytical thinking and the metric pipeline; a Tableau version proves the tooling fluency hiring managers screen for. Together they answer two distinct objections:

- *"Can they think analytically about SaaS retention and sales?"* — Streamlit dashboard.
- *"Can they ship in the tools we actually use?"* — Tableau workbook.

The workbook also makes the portfolio shareable through Tableau Public, where the audience overlaps directly with the role's hiring market.

## 3. Scope

**In scope:**
- Python pre-aggregation script that consumes `data/generated/*.csv` and writes flat, Tableau-friendly CSVs to `data/tableau/`.
- Three Tableau Public dashboards in one workbook: **Retention**, **Sales Performance**, **Pipeline**.
- Cross-dashboard navigation buttons.
- Custom Cadenza color palette installed via `Preferences.tps`.
- Publish to Tableau Public; add the public URL to the Streamlit About page and the project README.

**Out of scope (explicit):**
- Replicating every Streamlit chart. The Tableau version is deliberately leaner.
- Rep scorecard table, stage-to-stage conversion table, aging-deals table, territory balance heatmap, forecast bias by segment, MRR waterfall. Each was evaluated and dropped — reasons listed inline in §5.
- Tableau Server / Cloud deployment. Tableau Public is the publish target.
- New metric logic. Every metric in the Tableau version is computed in the existing `src/*.py` modules or is a trivial Tableau aggregation on raw data.
- Live database connections. Workbook reads CSV extracts only.

## 4. Architecture

### Data flow

```
data/generated/*.csv  (existing Streamlit-consumed files)
        │
        ▼
scripts/build_tableau_extracts.py  (new — calls existing src/*.py modules)
        │
        ▼
data/tableau/*.csv  (new — flat, Tableau-friendly)
        │
        ▼
cadenza.twbx  (Tableau workbook — 3 dashboards, ~8 worksheets)
        │
        ▼
Tableau Public  (publish — final URL set at publish time)
```

### Why pre-aggregation, not pure-Tableau LOD

The hard metrics (NRR, GRR, cohort retention, ramp curve, forecast accuracy) already exist as pure pandas functions in `src/metrics.py`, `src/cohorts.py`, `src/forecast.py`, `src/quota.py`. Re-implementing them as Tableau Level-of-Detail expressions would burn 4-6 hours and risks subtle off-by-one drift from the Streamlit version. Pre-aggregating to flat CSVs makes Tableau's job pure visualization, keeps metric definitions identical across both products (one source of truth), and matches the few-hour build budget.

Filters that need to recompute aggregations live (segment, channel, quarter) operate on **raw** opportunity / rep data, which Tableau handles trivially. This is the hybrid model: pre-aggregate the gnarly metrics, leave the simple aggregations to Tableau.

### Files Tableau reads

**Pre-aggregated** (5 files, generated by `scripts/build_tableau_extracts.py`):

| File | Grain | Used by |
|---|---|---|
| `tableau_monthly_metrics.csv` | one row per month | Dashboard 1 KPIs + NRR trend |
| `tableau_cohort_retention.csv` | (signup_cohort × channel × month_offset) | Dashboard 1 heatmap + M12 bar |
| `tableau_rep_attainment.csv` | (rep × quarter) | Dashboard 2 attainment bar + KPI |
| `tableau_ramp_curve.csv` | tenure-month bucket | Dashboard 2 ramp curve |
| `tableau_forecast_accuracy.csv` | (quarter × forecast_category) | Dashboard 2 forecast chart + KPI |

**Raw** (3 files, copied from `data/generated/`):

| File | Used by |
|---|---|
| `opportunities.csv` | Dashboard 3 pipeline-by-stage, win-rate-by-segment, KPI tiles |
| `opportunity_stage_history.csv` | Dashboard 3 stage velocity |
| `reps.csv` | Dashboard 2 (joined to rep_attainment for labels) |

## 5. Dashboard designs

### Dashboard 1 — Retention

```
┌─────────────────────────────────────────────────────────┐
│  Cadenza Retention                          [→ Sales]   │
├─────────────────────────────────────────────────────────┤
│  [Current MRR]  [NRR (TTM)]  [GRR (TTM)]  [Logo Ret.]   │
├─────────────────────────────────────────────────────────┤
│  Filter: Acquisition Channel  ▼ (All)                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Cohort Retention Heatmap                               │
│  (rows = signup cohort YYYY-MM, cols = months since     │
│   signup, color = retention %.  Q3 2024 Self-Serve      │
│   row pops red when channel filter = Self-Serve Promo)  │
│                                                         │
├──────────────────────────────┬──────────────────────────┤
│  M12 Retention by Channel    │  NRR Trend Over Time     │
│  (bar, sorted desc, color    │  (line, 100% reference,  │
│   by channel)                │   monthly cadence)       │
└──────────────────────────────┴──────────────────────────┘
```

**Insight delivered:** Q3 2024 Self-Serve Promo cohort churns at ~2× the rate of other channels. Surfaces when the user clicks "Self-Serve Promo" in the channel filter — the Q3 2024 row in the heatmap drops to red, and the M12-by-channel bar shows Self-Serve Promo at the bottom.

**Worksheets needed:**
1. Cohort heatmap (`tableau_cohort_retention.csv`)
2. M12 retention by channel (filtered view of same dataset, months_since_signup = 12)
3. NRR trend line (`tableau_monthly_metrics.csv`)
4. KPI tiles × 4 (current MRR, NRR TTM, GRR TTM, Logo Retention TTM — all from `tableau_monthly_metrics.csv`)

**Dropped from Streamlit version:**
- MRR Waterfall — visually loud, insight lives elsewhere.
- Segment drilldown — channel is the engineered insight; segment is a sibling, not the driver.

## 6. Pre-aggregation script

Path: `scripts/build_tableau_extracts.py`

**Responsibilities:**
1. Load `data/generated/*.csv`.
2. Call existing functions from `src/metrics.py`, `src/cohorts.py`, `src/forecast.py`, `src/quota.py` to compute aggregates.
3. Write the five pre-aggregated CSVs to `data/tableau/` in long format.
4. Copy `opportunities.csv`, `opportunity_stage_history.csv`, `reps.csv` to `data/tableau/` so the entire workbook reads from one directory.
5. Idempotent — re-running produces byte-identical output.

**Outputs and grain:**

| File | Columns | Approx rows |
|---|---|---|
| `tableau_monthly_metrics.csv` | month, total_mrr, new_mrr, expansion_mrr, contraction_mrr, churn_mrr, nrr, grr, logo_retention | 36 |
| `tableau_cohort_retention.csv` | signup_cohort, acquisition_channel, months_since_signup, retention_pct, n_customers | ~3,500 |
| `tableau_rep_attainment.csv` | rep_id, quarter, closed_won_amount, quarterly_quota, attainment_pct, tenure_months_at_quarter_end | ~150 |
| `tableau_ramp_curve.csv` | tenure_month_bucket, median_attainment_pct, n_data_points, segment_specialty (SMB) | ~18 |
| `tableau_forecast_accuracy.csv` | quarter, forecast_category, forecasted_amount, actual_amount, accuracy_pct | ~36 |

**Testing:** one pytest test per output file asserting (a) expected row count is in band, (b) no NaN in non-nullable columns, (c) a known metric value matches the Streamlit version's hand-computed expected value. Tests live in `tests/test_tableau_extracts.py`.

## 7. Brand identity & formatting

### Color palette (Cadenza)

Install in Tableau via `~/Documents/My Tableau Repository/Preferences.tps`:

| Token | Hex | Use |
|---|---|---|
| `CADENZA_PRIMARY` | `#1F3A8A` | Default bar color, primary line |
| `CADENZA_ACCENT` | `#06B6D4` | Secondary line / category |
| `CADENZA_GOOD` | `#10B981` | Above-target / positive delta |
| `CADENZA_BAD` | `#EF4444` | Below-target / negative delta |
| `CADENZA_NEUTRAL` | `#94A3B8` | Reference lines, gridlines, axis text |

### Format conventions

- Percent metrics: `0.0%` (one decimal).
- Dollar metrics: `$#,##0` (no decimals, comma thousands).
- Bars with potential 0-values: text labels enabled so empty bars still show `0%`.
- Reference lines: thin (1px), dashed, color `CADENZA_NEUTRAL`, with axis-anchored annotation.
- Reference-line annotations within ~3 months of each other: stagger using top-left / top-right alignment.
